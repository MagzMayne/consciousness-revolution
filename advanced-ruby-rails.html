🎯 Core Principles

Ruby on Rails is built on two pillars that make development fast, consistent, and maintainable. These aren't just guidelines — they're baked into Rails itself.

🏛️ CoC — Convention over Configuration

Rails assumes sensible defaults so you don't have to configure every detail.

  • Model User → table users automatically
  • Controller UsersController → /users routes
  • File paths follow strict naming conventions
  • Less boilerplate · faster onboarding · consistent structure

♻️ DRY — Don't Repeat Yourself

Write logic once and share it everywhere — no copy-paste.

  • Shared behaviour in Concerns (modules)
  • Reusable view snippets in partials
  • Business logic centralised in models
  • Complex workflows in service objects

🗺️ CoC: One Keyword → Seven Routes

A single resources :articles declaration in config/routes.rb generates all seven RESTful routes automatically — no manual configuration.

📝
resources :articles
→
7 routes
GET · POST · PATCH · DELETE
→
ArticlesController
index · show · new · create
edit · update · destroy
📄 config/routes.rb — Convention-driven routing
# ONE line → 7 RESTful routes (CoC)
resources :articles

# Generates automatically:
#  GET    /articles          → ArticlesController#index
#  GET    /articles/new      → ArticlesController#new
#  POST   /articles          → ArticlesController#create
#  GET    /articles/:id      → ArticlesController#show
#  GET    /articles/:id/edit → ArticlesController#edit
#  PATCH  /articles/:id      → ArticlesController#update
#  DELETE /articles/:id      → ArticlesController#destroy

# Nested resource (comments belong to articles)
resources :articles do
  resources :comments, only: %i[index create destroy]
end

# Limit actions to reduce surface area
resources :users, only: %i[index show create destroy]
📄 CoC: Model → Table Naming (no config needed)
# Class name     → Table name (automatic)
# User           → users
# BlogPost       → blog_posts
# LineItem       → line_items
# AdminUser      → admin_users

class User < ApplicationRecord   # → table "users"
end

class BlogPost < ApplicationRecord # → table "blog_posts"

class LegacyUser < ApplicationRecord
  self.table_name = 'tbl_users'  # explicit override
end

♻️ DRY: Concerns — Share Behaviour Across Models

Instead of copy-pasting the same methods into every model, extract shared behaviour into a Concern and include it with one line.

📄 app/models/concerns/auditable.rb
# DRY: one definition — used by any model that needs audit trails
module Auditable
  extend ActiveSupport::Concern

  included do
    belongs_to :creator, class_name: 'User', optional: true
    belongs_to :updater, class_name: 'User', optional: true

    before_create :set_creator
    before_update :set_updater
  end

  def created_by?(user)
    creator_id == user.id
  end

  private

  def set_creator
    self.creator_id = Current.user&.id
  end

  def set_updater
    self.updater_id = Current.user&.id
  end
end
📄 app/models/concerns/publishable.rb
# DRY: publish/unpublish behaviour shared by Article, Video, Podcast…
module Publishable
  extend ActiveSupport::Concern

  included do
    # DRY scopes — defined once, available on every including model
    scope :published, -> { where(published: true) }
    scope :draft,     -> { where(published: false) }
    scope :recent,    -> { order(published_at: :desc).limit(10) }

    validates :published_at, presence: true, if: :published?
  end

  def publish!
    update!(published: true, published_at: Time.current)
  end

  def unpublish!
    update!(published: false, published_at: nil)
  end
end
📄 app/models/article.rb — Include concerns with one line each
class Article < ApplicationRecord
  # DRY: one line adds audit trail + publish behaviour
  include Auditable
  include Publishable
  include Taggable

  belongs_to :author, class_name: 'User'
  has_many   :comments, dependent: :destroy

  # DRY: validations live here, not in controllers
  validates :title, presence: true, length: { maximum: 200 }
  validates :body,  presence: true

  # DRY: scope defined once, used everywhere
  scope :by_author, ->(user) { where(author: user) }
end

# Video and Podcast get the SAME publish behaviour for FREE:
class Video   < ApplicationRecord; include Publishable; end
class Podcast < ApplicationRecord; include Publishable; end

♻️ DRY: ApplicationController — Shared Controller Logic

Put authentication, pagination, and error handling in the base controller so every child controller inherits it — no duplication.

📄 app/controllers/application_controller.rb
class ApplicationController < ActionController::Base
  # DRY: authentication wired once, inherited by every controller
  before_action :authenticate_user!

  private

  # DRY: pagination helper used by any index action
  def paginate(scope)
    scope.page(params[:page]).per(params.fetch(:per_page, 25))
  end

  # DRY: uniform JSON error response — one method, many callers
  def render_error(message, status:)
    render json: { error: message }, status: status
  end
end
📄 app/controllers/articles_controller.rb — Thin controller
class ArticlesController < ApplicationController
  # CoC: action names map directly to HTTP verbs via routes.rb
  # DRY: before_action runs shared logic once, not in every action
  before_action :set_article, only: %i[show edit update destroy publish]
  before_action :require_ownership!, only: %i[edit update destroy]

  def index
    @articles = paginate(Article.published.includes(:author))
  end

  def show; end   # @article already set by before_action

  def create
    # DRY: delegate complex workflow to service object
    result = Articles::CreateService.call(params: article_params, user: current_user)
    result.success? ? redirect_to(result.article) : render(:new)
  end

  def publish
    # DRY: publishing logic lives in service, not here
    Articles::PublishService.call(@article)
    redirect_to @article, notice: 'Article published!'
  end

  private

  # DRY: one place for strong parameters
  def article_params
    params.require(:article).permit(:title, :body, tag_ids: [])
  end

  def set_article
    @article = Article.find(params[:id])
  end

  def require_ownership!
    render_error('Forbidden', status: :forbidden) unless @article.created_by?(current_user)
  end
end

♻️ DRY: Service Objects — Extract Complex Workflows

When an action involves multiple steps (create + tag + notify + audit), extract it into a service object so the workflow lives in ONE place.

📄 app/services/articles/publish_service.rb
module Articles
  class PublishService
    # DRY: the "publish an article" multi-step workflow lives here,
    # not scattered across controllers, jobs, or mailers.

    def self.call(article, notifier: ArticleMailer)
      new(article, notifier: notifier).call
    end

    def initialize(article, notifier:)
      @article  = article
      @notifier = notifier
    end

    def call
      ActiveRecord::Base.transaction do
        @article.publish!           # from Publishable concern
        notify_followers
        create_activity_log
      end
      { ok: true, article: @article }
    rescue StandardError => e
      { ok: false, error: e.message }
    end

    private

    def notify_followers
      @notifier.article_published(@article).deliver_later
    end

    def create_activity_log
      ActivityLog.create!(
        resource: @article,
        event: 'published',
        user: Current.user
      )
    end
  end
end

♻️ DRY: Helpers — Shared View Logic

Common formatting and display helpers live in one module and are automatically available in all views.

📄 app/helpers/application_helper.rb
module ApplicationHelper
  # DRY: format dates consistently across every view
  def formatted_date(time)
    time.strftime('%B %-d, %Y')
  end

  # DRY: truncate long text — one definition used everywhere
  def truncated_body(text, length: 160)
    truncate(text, length: length, separator: ' ')
  end

  # DRY: status badge HTML — renders consistently site-wide
  def status_badge(resource)
    label, css = resource.published? ? ['Published', 'badge-success']
                                     : ['Draft',     'badge-secondary']
    content_tag(:span, label, class: ['badge', css])
  end

  # DRY: human-readable file sizes
  def human_size(bytes)
    number_to_human_size(bytes)
  end
end

The full demonstration file below runs standalone (no Rails install required) and prints live output for every principle shown above.

📄 language-samples/rails_coc_dry.rb — run with: ruby rails_coc_dry.rb
# Ruby on Rails — Convention over Configuration (CoC) & DRY
# BarbrickDesign - Complete Language Portfolio

# ─── DRY: Concerns ───────────────────────────────────────────

module Auditable
  def self.included(base)
    base.extend(ClassMethods)
    base.instance_variable_set(:@auditable, true)
  end
  module ClassMethods
    def auditable?; @auditable; end
  end
  def audit_log
    "[#{self.class.name}##{object_id}] last touched at #{Time.now}"
  end
end

module Publishable
  def self.included(base)
    base.extend(ClassMethods)
  end
  module ClassMethods
    # DRY scopes — defined once, reused by every model
    def published; all.select(&:published?); end
    def draft;      all.reject(&:published?); end
  end
  def publish!;   @published = true;  self; end
  def unpublish!; @published = false; self; end
  def published?; !!@published; end
end

# ─── CoC: Model Naming ────────────────────────────────────────

class ApplicationRecord
  def self.table_name   # simulates ActiveRecord convention
    name.gsub(/([A-Z])/, '_\1').downcase.sub(/^_/, '') + 's'
  end
end

class User < ApplicationRecord   # → "users"
  include Auditable
  attr_accessor :id, :name, :email, :role
  VALID_ROLES = %w[user moderator admin].freeze

  def initialize(id:, name:, email:, role: 'user')
    @id = id; @name = name; @email = email; @role = role
  end

  # DRY: validations in the model, not in controllers
  def errors
    [].tap do |e|
      e << 'Name required'             if name.to_s.strip.empty?
      e << 'Email must include @'       unless email.to_s.include?('@')
      e << "Role must be #{VALID_ROLES}" unless VALID_ROLES.include?(role)
    end
  end

  def valid?; errors.empty?; end
end

class Article < ApplicationRecord  # → "articles"
  include Auditable
  include Publishable
  attr_accessor :id, :title, :body

  def initialize(id:, title:, body:)
    @id = id; @title = title; @body = body
  end

  def self.all; @store ||= []; end
  def save; self.class.all << self; self; end
end

# ─── DRY: Service Object ──────────────────────────────────────

class ArticlePublisher
  def initialize(article, notifier: nil)
    @article = article; @notifier = notifier
  end

  def call
    @article.publish!
    @notifier&.call("Published: #{@article.title}")
    puts "  [AUDIT] #{@article.audit_log}"
    { ok: true, article: @article }
  rescue => e
    { ok: false, error: e.message }
  end
end

🚀 Key Takeaways

🏛️ CoC Benefits

  • Zero configuration boilerplate
  • Consistent project structure
  • New developers onboard faster
  • Rails conventions are an industry standard

♻️ DRY Benefits

  • One bug fix → fixed everywhere
  • Smaller, focused classes
  • Easier unit testing
  • Clearer separation of concerns

🔑 Patterns Used

  • ActiveSupport::Concern
  • RESTful resource routing
  • Service objects
  • ApplicationController base
  • Model scopes & validations
  • Helper modules

📐 Rails File Conventions

  • app/models/user.rb → User
  • app/controllers/users_controller.rb
  • app/views/users/index.html.erb
